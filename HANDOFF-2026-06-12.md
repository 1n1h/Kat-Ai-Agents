## 1. Mobile specialist dropdown (PRs #1, #2)

**Symptom:** Tapping "Orchestrated" on a phone showed nothing / a clipped menu.

**Files:** `components/AgentSelect.tsx`

**What & why:**
- The panel was anchored `right-0` to a trigger that sits mid-row in the composer, so on narrow phones it spilled off the left edge.
- First attempt used `position: fixed` with measured coordinates — but the composer lives inside a `.rise` wrapper whose lingering `transform` becomes the containing block for fixed children, so fixed coords landed off-screen.
- **Final fix:** render the panel through a **React portal to `document.body`** (escapes the transformed ancestor), positioned with viewport-clamped fixed coords measured from the trigger (`place()` on open + resize/scroll). Outside-click handler checks both the trigger ref and the portaled panel ref.

## 2. iOS text-to-speech playback (PRs #3, #4)

**Symptom:** Voice-mode replies and the read-aloud speaker button returned text but **no audio on iPhone**.

**Files:** `lib/audioPlayback.ts` (new), `components/TurnActions.tsx`, `components/VoiceMode.tsx`, `components/Composer.tsx`

**What & why:**
- Both paths call `/api/tts` then `audio.play()` **after** an `await` — iOS Safari revokes the tap's activation by then and silently blocks playback.
- New `lib/audioPlayback.ts`: one shared `<audio>` element, "unlocked" by playing a tiny silent clip **synchronously inside the tap** (`primeAudioPlayback`), then reused for the real audio (`playAudioUrl`). One shared element also enforces one-thing-speaks-at-a-time.
- Priming is wired into the voice button (`Composer`), the voice orb (`VoiceMode`), and the read-aloud button (`TurnActions`).
- **Critical detail:** the unlock clip must play **unmuted** (it's digital silence, so inaudible). A muted unlock does NOT grant audible playback on iOS — that was a real bug fixed in #4.

**⚠️ Still possibly server-side:** TTS may also fail if the ElevenLabs key lacks **Text-to-Speech permission** or has **no credits**. STT (speech-to-text) works on the same key, so the key is valid for STT at least. If audio still doesn't play after a fresh load, check: ElevenLabs key has TTS permission + the account has credits. (`/api/tts` falls back from local Kokoro to ElevenLabs in the cloud.)

## 3. Cloud "Orchestrated" mode (PR #4)

**Symptom:** With "Orchestrated" selected on the deployed app, replies came from named specialists ("Sol Vance here", "I'm Vera") — the cloud path routed straight to one specialist persona; the orchestrator was never involved.

**Files:** `app/api/chat/route.ts`

**What & why:**
- The local install runs the real orchestrator (Atlas) via the Agent SDK `Task` tool. The Agent SDK is excluded from Vercel bundles, so cloud uses the direct Anthropic API.
- Rewrote the cloud `auto` path into an **orchestrator tool-use loop**: a cloud orchestrator system prompt + a `consult_specialist` tool. The orchestrator consults specialists privately (each a sub-call to that persona's prompt), then synthesizes **one answer in its own voice**. Status lines (`consulting: …`) stream to the UI, mirroring the local pipeline.
- Persona first-names (Sol/Cass/Lex/Vera) are kept internal via an `identityNote`; a directly-chosen specialist answers under its professional role.

## Gotchas (this session)

- **Squash-merge re-merge hazard:** because PRs are squash-merged, re-syncing the work branch with `main` repeatedly produced conflicts and once **auto-duplicated `<TrustBar/>`** in `LandingPage.tsx`. After any `git merge origin/main`, grep for conflict markers AND eyeball `LandingPage.tsx` for duplicated sections.
- `.rise`/`.reveal`/`.card-hover` all animate `transform`; never put two transform-animating classes on the same element — wrap instead (reveal outer, hover inner).
- `position: fixed` inside the composer/landing breaks under transformed ancestors (`.rise`) — use a portal (see `AgentSelect`).
- Marquee renders its children **twice** (for the seamless loop) — that's intentional, not a duplicate-content bug.
- Persona names stay internal; UI uses professional roles. (Unchanged rule, reinforced in the cloud orchestrator + identity notes.)
